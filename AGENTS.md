# AGENTS.md

Guidance for AI coding agents (and humans) working on this repository.

## Project

**Wortschatz** is a Flutter app for iOS and Android for learning German vocabulary, in an arcade style (blue gradient ground, white cards, orange calls to action). See `README.md` for the features.

Stack: Flutter (stable, pinned in `.github/workflows/build.yml`), Dart 3, `flutter_riverpod` 3, `flutter_tts`, `shared_preferences`. No code generation.

## Commands

```sh
flutter pub get
dart format lib test tool     # CI fails on unformatted code
flutter analyze               # must report "No issues found!"
flutter test                  # all tests must pass
```

Run format, analyze and test before every commit.

## Layout

```
lib/
  main.dart            loads SharedPreferences and the word asset, overrides their providers
  app.dart             MaterialApp and the bottom navigation (Words, Practice, Settings)
  models/word.dart     Word, Gender
  data/                asset parsing, 50-word lists
  games/               pure game logic: hive.dart, spelling.dart, quiz.dart
  providers/           Riverpod state: progress (Leitner), stats (points/level/streak), settings, speech
  screens/             home, word list, learn, spelling, der_die_das, hive, fallee, settings
  widgets/             BlueScaffold and shared widgets
  theme/app_theme.dart every colour (AppColors) and buildTheme()
assets/words_de.json   generated by tool/import_lernle.dart; don't edit by hand
assets/audio/de/       one <word id>.mp3 per word + manifest.json, from tool/import_lernle_audio.dart
lib/content/           ContentSource: words, clips, pictures (bundled now, CDN later)
test/                  helpers.dart, data_test, games_test, providers_test, app_test
```

## Rules

- **Words come from lernle's reviewed deck** (`Pratiyush/lernle`, `content/lemmas/de.jsonl`). Regenerate the asset with `tool/import_lernle.dart`. Never import `de_tobo.jsonl` (pending review) and never hand-invent words or translations.
- Store progress under **lernle word ids** (`de.zeit.n`), never list indices. Never rename an id.
- Riverpod: `Notifier`/`NotifierProvider`, `Provider`, `Provider.family`. No legacy `StateProvider`/`StateNotifierProvider`, no generators. Persisted state reads `sharedPreferencesProvider` in `build()` and writes through on every mutation.
- **Content goes through `ContentSource`** (`lib/content/content_source.dart`, `contentSourceProvider`): the word list, audio clips and (future) pictures, keyed by Lernle word id. Today it's `BundledContentSource` (assets). The shared `../content` repo on a CDN will become a second implementation, so never load content assets directly from a screen or provider.
- **Speech goes through `speakerProvider`**: `sayWord(word)` plays the word's recorded clip (Lernle's ElevenLabs render; nouns include their article) through `AudioEngine`. Device TTS (`SpeechEngine`) is only for example sentences and is a logged fallback for a word without a clip. Never use `FlutterTts` or `AudioPlayer` directly. Tests use `FakeSpeechEngine`, `FakeAudioEngine` and `FakeContentSource`.
- Clips come from `../lernle/app/assets/audio/de` via `tool/import_lernle_audio.dart` (read-only on Lernle). Never import from `lernle/harvest/` (reference-app audio) and never call the ElevenLabs API.
- Time comes from `clockProvider` so tests can move between days.
- Keep game rules in `lib/games/` as pure Dart with unit tests; screens only hold short-lived UI state.
- Every colour lives in `lib/theme/app_theme.dart`. Der/die/das use the German flag colours (black, red, gold).
- **Ads (owner policy, 2026-11-08):** personalised AdMob ads behind Google UMP consent and, on iOS, the App Tracking Transparency prompt. Everything sits behind a compile-time `ADS_ENABLED` flag (`--dart-define=ADS_ENABLED=true`) that stays **off** until Pratiyush creates the AdMob apps and ad units. Debug builds use Google's test unit ids. The ads code is not built yet. When it is, it needs:
  - `google_mobile_ads` (bundles the UMP SDK) and an `AdsService` behind a Riverpod provider with a no-op fake for tests, the same pattern as `SpeechEngine`.
  - Placements: a banner on Home, Word list and Settings; an interstitial after a finished Hive / Der Die Das / Fallee round, capped and never in the first session or mid-round; rewarded only for extras (hint/skip, streak freeze). Never during Learn or Practice answers.
  - Android: `com.google.android.gms.ads.APPLICATION_ID` meta-data in `AndroidManifest.xml`. The `AD_ID` permission comes from the SDK.
  - iOS: `GADApplicationIdentifier`, `NSUserTrackingUsageDescription` and `SKAdNetworkItems` in `Info.plist`. Request ATT after UMP consent.
  - A "Privacy & ad choices" entry in Settings that reopens the UMP form, a privacy policy that names AdMob, `app-ads.txt` on the developer site, and updated Play Data safety and App Privacy answers.
- No paywall, and nothing locked behind points or ads.
- Layouts must work at 360 dp width. British spelling in UI copy ("practise", "favourites").
- New logic needs a unit test; new screens need a widget test (`buildApp` / `buildScreen` in `test/helpers.dart`).
- Android declares the `TTS_SERVICE` query in `AndroidManifest.xml` (needed on Android 11+). Don't remove it.
- Don't commit build outputs (`build/`, `.apk`, `.ipa`). CI builds them.
